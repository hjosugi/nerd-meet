# プライバシー設計

このドキュメントは方針の宣言ではなく、コードのどこで何が起きるかの索引です。
記述と実装が食い違っていたら、それはバグとして報告してください。

## 保持するもの

| データ | 形式 | 場所 |
| --- | --- | --- |
| ハンドル | 平文 | `users.handle` |
| 本人確認の証明書シリアル | SHA-256 ハッシュ | `users.identity_serial_hash` |
| 生年 | 年のみ（生年月日は受け取らない） | `users.birth_year` |
| 居住地 | 都道府県のみ（住所は受け取らない） | `users.prefecture` |
| メッセージ | AES-256-GCM 暗号文 | `messages.ciphertext` |
| メッセージの類似度指紋 | 鍵付き一方向 SimHash（64bit） | `messages.fingerprint` |
| サインイン履歴 | 国・緯度経度・スコア・判断 | `auth_events` |
| 平文閲覧の記録 | 誰が・いつ・何を・なぜ | `audit_logs` |

## 保持しないもの

- **顔写真** — 列がありません。画像アップロードの経路もありません
- **生年月日・住所の詳細** — 本人確認プロバイダから受け取る時点で年と都道府県に落とします
- **証明書シリアルそのもの** — ハッシュだけを保存するので、証明書レジストリと突合できません
- **メッセージ平文** — どこにも書き込まれません
- **足あと・オンライン状態** — 実装していません

## 削除が何をするか

`NerdMeet.Privacy.Deletion.delete_account/2`:

1. 対象者が参加している全会話の `conversation_keys` 行を削除（**これが本体**）
2. プロフィール、保存クエリ、いいね、クレデンシャルを削除
3. `users` を `deleted` にし、位置情報を消す
4. 監査ログに「いくつの会話を破棄したか」を記録

暗号文はバックアップに残る可能性があります。それは正直に書くべき事実です。
残らないのは、それを開く手段のほうです。

`Deletion.shredded?/1` はこの性質を外から確認する関数で、テストが直接 assert しています。

### 自主退会と利用停止の非対称

自主退会は本人確認ハッシュを消します。戻ってこられるようにするためです。
利用停止は残します。同じ証明書で再登録されないようにするためです。
どちらも個人データの削除ですが、片方は強制措置でもあります。

## 運営が読めるもの、読めないもの

レビューのために平文を読むことは可能です。`Moderation.read_plaintext/3` がその唯一の経路で、
呼ぶたびに `audit_logs` に行が書かれます。理由は必須で、長さ検証があります
（全行の理由が「確認」になっている監査ログは何も記録していないのと同じだからです）。

鍵が破棄された会話は運営にも読めません。`read_plaintext/3` は `{:error, :unreadable}` を返します。

本番では `audit_logs` に対する UPDATE / DELETE 権限を剥奪する運用を前提にしています。
→ `docs/ISSUES.md` P0

## ディレクトリで公開されるもの

`NerdMeet.Publishing.exported_fields/0` に列挙されたフィールドだけです。
都道府県・生年・経験年数は**バンド化された値に置き換えられ**、正確な値は書き出されません。
`user_id` も含まれません。

k 未満のグループは、最も粗いバンドでも足りなければ公開されません。

## 検索条件はサーバーに送られない

ディレクトリ検索は公開スナップショット（静的 JSON）に対してブラウザ内で実行されます。
「誰が何を条件に探したか」はサーバーに残りません。

## 第三者への送信

既定では**ゼロ**です。外部フォント、解析、CDN、いずれも読み込みません（CSP がそれを強制しています）。
モデレーション段3にモデルを設定した場合のみ、その分類器にメッセージ本文が渡ります。
既定の `Classifier.Null` は外部通信をしません。

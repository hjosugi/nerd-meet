# アーキテクチャ

## コンテキスト境界

```
NerdMeet.Accounts     本人確認、パスキー、リスク評価、セッション記録
NerdMeet.Members      プロフィール、保存クエリ、ディレクトリ検索
NerdMeet.Social       いいね、マッチ、ブロック、通報
NerdMeet.Chat         会話、暗号化メッセージ、送信可否
NerdMeet.Moderation   3段カスケード、強制措置、監査ログ
NerdMeet.Privacy      k-匿名化、暗号学的削除
NerdMeet.Publishing   静的スナップショットの生成
NerdMeet.Vault        AES-256-GCM、鍵の包み・解き、フィンガープリント
```

境界は「何を守るか」で切ってあります。`Accounts` は「本人か」を、`Chat` は「送ってよいか」を、
`Privacy` は「外に出してよいか」を担当します。
たとえば「マッチしていない相手には送れない」は Web 層ではなく `Chat` にあります。
コントローラに置いた制約は、新しいコントローラが1つ増えた時点で守られなくなるからです。

## メッセージ送信のフロー

```
send_message/3
  ├─ validate_body           空・長すぎを弾く
  ├─ authorize               マッチ済み / ブロックなし / 制限なし
  ├─ ensure_conversation     会話と会話鍵を必要になった時点で作る
  ├─ Moderation.screen       段1（正規表現・同期）
  │    └─ :block なら理由を返してここで終了
  ├─ Vault.seal              AES-256-GCM で封じる
  ├─ Vault.fingerprint       一方向の SimHash（段2用）
  ├─ Repo.insert             暗号文だけを保存
  └─ Oban.insert             段2・段3を非同期で予約
```

同期経路にあるのは段1だけです。モデレーションが体感できる遅延になった時点で、
人はそれを迂回する経路を探し始めます。

## モデレーション3段の役割分担

**段1（`Moderation.Rules`）** — 本文のパターン照合。
`Moderation.Text` が NFKC 正規化・小文字化・カタカナ→ひらがな畳み込みを行い、
「区切り文字を保った形」と「区切り文字を全部落とした形」の2つを作ります。
前者は `line` と `pipeline` を区別するため、後者は `ら　い　ん` を `らいん` に戻すためです。

Elixir の正規表現は Unicode プロパティが有効なので `\b` は日本語の隣で境界になりません。
ASCII 境界は `(?<![a-z0-9_])` と明示的に書いてあります。これは実装中に踏んだ罠です。

**段2（`Moderation.Signals`）** — 本文を読まない。
送信先の分散度、定型文率、マッチから初回送信までの時間、通報者数、段1ヒット率。
定型文率は `Vault.fingerprint/1` の SimHash 同士のハミング距離で測るため、
「同じ文面を50人に送っているか」を本文を復号せずに判定できます。

**段3（`Moderation.Classifier`）** — 差し替え可能な behaviour。
既定実装 `Null` は外部通信を一切せず、判定を保留してレビューキューに残します。
メッセージを第三者に送るかどうかは運営者が明示的に決めてプライバシーポリシーに書くべきことなので、
リポジトリの既定値にはできません。

## 強制措置の段階

```
段1ヒット        → 送信拒否 + 理由の提示（大半の善意ユーザーはここで止まる）
スコア超過       → シャドウ制限（検索から消える。アカウントは動く）+ レビューキュー
確定違反         → アカウント停止 + 本人確認ハッシュ保持による再登録拒否
```

シャドウ制限は「BAN されたと気づかせない」ためです。
気づいた業者は1時間で再登録しますが、サービスが自分に効いていないだけだと思った業者はずっと遅い。

## 暗号化と鍵

```
VAULT_MASTER_KEY (環境変数)
        │ wrap
        ▼
conversation_keys.wrapped_key   ← 会話ごとに1行
        │ unwrap
        ▼
data key ──seal──▶ messages.ciphertext / iv / tag
```

マスター鍵はデータキーを包むためだけに使われ、データベースには存在しません。
データベースのダンプ単体では何も開けません。
`conversation_keys` の行を消すことが削除であり、それ以上でも以下でもありません。

## k-匿名化のバンド階梯

| バンド | 地域 | 年齢 | 経験年数 |
| --- | --- | --- | --- |
| fine | 都道府県 | 5年区切り | 2年区切り |
| medium | 地方 | 10年区切り | 5年区切り |
| coarse | 日本 | 1990年前後 | 3年未満 / 3〜9年 / 10年以上 |

各行は「グループが k 人以上になる最も細かいバンド」で公開されます。
最も粗いバンドでも k に届かない行だけが抑制されます。
`Anonymity.violations/2` はこの性質を直接検査するためにあり、テストはそれを assert しています。

## 公開スナップショット

検索はサーバーへのクエリではなく、公開された静的ファイルに対してブラウザ内で実行されます。
性能のためではありません。スナップショットは誰でもダウンロードして中身を確認できる固定物であり、
「ディレクトリが実際に開示しているのはこれだけです」という主張が検証可能になります。
サーバー側の検索 API は、自分についてこの主張ができません。

書き出されるフィールドは `Publishing.exported_fields/0` に列挙されています。
`profiles` に列を足しても、この配列を変えない限りエクスポートには現れません。

## 非同期ジョブ

Oban のキューは3つ。`moderation`（段2・段3）、`snapshots`（スナップショット再生成）、
`deletion`（鍵の破棄）。削除がジョブなのは、リクエストが切れても削除が完了するようにするためです。
タブを閉じた人も、確かに削除しています。

## 外部呼び出しとトランザクション

`Accounts.register/1` は本人確認プロバイダを**トランザクションの外で**呼びます。
政府側エンドポイントへのネットワーク往復のあいだデータベース接続を握り続けると、
向こうのレイテンシがこちらの障害になります。
`IdentityProvider` が behaviour なのはテストのためだけではなく、この境界を明示するためです。

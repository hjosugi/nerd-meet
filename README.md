# nerd-meet

顔写真ではなく**条件**で探す、エンジニア向けマッチング基盤。Elixir / Phoenix / PostgreSQL。

スワイプもレコメンドもありません。検索条件を書き、その条件を SQL としてプロフィールに公開でき、
相手の条件と自分の条件を突き合わせて「互いに条件を満たすか」を判定します。

## なぜ OSS なのか

マッチングサービスは「運営を信じてください」で成り立っています。本人確認は本当にしているのか、
メッセージは誰が読めるのか、退会したらデータは本当に消えるのか。どれも外からは検証できません。

このリポジトリはその答えをコードで示すために公開されています。
モデレーションの規則も、匿名化の閾値も、削除が何をするのかも、すべてここで読めます。
AGPL-3.0 なので、改変して運用する場合はその改変も公開する必要があります。

## 設計の中心にある4つの判断

### 1. モデレーションは3段カスケード

| 段 | 手法 | 対象 | コスト |
| --- | --- | --- | --- |
| 1 | 正規表現（同期・送信経路上） | 全メッセージ | ほぼゼロ |
| 2 | 集計クエリ（非同期） | 全メッセージ | ほぼゼロ |
| 3 | モデル判定（非同期） | 1〜3% | 実コスト |

全メッセージを LLM に投げると費用が破綻します。安い段で 99% を素通しさせ、
残ったものにだけ高い判定を使うことで初めて成立します。

段1は日本語の回避手法を前提に作られています。全角（`Ｊ　Ｋ`）、分かち書き（`ら　い　ん　ＩＤ`）、
助詞の挟み込み（`LINE の ID は abc_123`）はすべて NFKC 正規化とカタカナ畳み込みの後に照合されます。
一方で「オンライン勉強会」や「サポートしています」は通ります。
→ [`lib/nerd_meet/moderation/rules.ex`](lib/nerd_meet/moderation/rules.ex)

段2は本文を一切読みません。送信先の分散度、定型文率、マッチ直後の送信、通報密度。
業者は文面を変えられても行動を変えられないので、実際に効くのはこちらです。
類似度判定は本文ではなく一方向のフィンガープリント同士で行われます。
→ [`lib/nerd_meet/moderation/signals.ex`](lib/nerd_meet/moderation/signals.ex)

### 2. 削除は鍵の破棄

メッセージは**会話ごとの鍵**で AES-256-GCM 暗号化されます。削除はその鍵を消すことです。
暗号文はバックアップに残るかもしれませんが、誰にも開けません。運営にもです。

これは「消しました」という約束ではなく、構造的な性質です。テストで直接確認できます。
→ [`lib/nerd_meet/privacy/deletion.ex`](lib/nerd_meet/privacy/deletion.ex)

自主退会は本人確認ハッシュを消して再登録できるようにし、
利用停止は残して同じ証明書での再登録を拒否します。どちらも削除ですが、意味が違います。

### 3. 公開は k-匿名化を通す

都道府県・生年・経験年数は単体では無害でも、組み合わせると個人が特定されます。
ディレクトリはバンド化した値だけを公開し、k 人未満のグループは公開しません。

**実装して初めて分かったこと：k-匿名化には人口密度の要件があります。**
数百人規模では組み合わせのほとんどが一意になり、素直に実装すると検索が機能しなくなります。
k を下げるのは間違いで、正解は粗いバンドから始めて人口とともに精度を上げることです。

```
$ mix nerd.demo 300      # 公開 99.7% / 詳細バンド 18.3%
$ mix nerd.demo 5000     # 公開 99.8% / 詳細バンド 87.0%
$ mix nerd.demo 20000    # 公開 100.0% / 詳細バンド 99.0%
```

→ [`lib/nerd_meet/privacy/anonymity.ex`](lib/nerd_meet/privacy/anonymity.ex)

### 4. 認証は摩擦を配分する

パスキーによる認証に、リスクスコアを重ねています。
いつもの国・いつもの端末なら摩擦はゼロ。国が変わり、物理的にありえない移動が起きていれば再認証。

署名カウンタが進まない場合だけは別扱いで、スコアではなく即座に全クレデンシャル失効です。
認証器が複製されている以上、許容できる閾値が存在しないためです。
→ [`lib/nerd_meet/accounts/risk.ex`](lib/nerd_meet/accounts/risk.ex)

## 機能の取捨選択

**採用**：相互いいねでマッチ成立、成立後のみチャット解禁、ブロック・通報、条件の保存と公開、相互条件マッチ。

**不採用**：

- スワイプ UI — 見た目で判断させる装置であり、顔写真を扱わない方針と矛盾します
- 「あなたへのおすすめ」— アルゴリズムで発見を制御することは自由検索の思想と正面から衝突します
- 足あと・オンライン表示 — 監視感が強く、プライバシー方針と両立しません
- ブースト・スーパーライク — 課金導線のために体験を歪めます

## 動かす

### Docker

```sh
docker compose up --build
open http://localhost:4000
```

### ローカル

必要なもの: Elixir 1.18 / OTP 27 / PostgreSQL 16。

```sh
mix setup                      # 依存取得・DB作成・マイグレーション・シード・アセット
mix phx.server
open http://localhost:4000
```

開発中は `/dev/session/hjosugi` でサインインできます（`:dev_routes` が真のときだけ生成されます）。

### よく使うコマンド

```sh
mix check              # CI と同じ検査を全部（format / credo / sobelow / audit / test）
mix test
mix nerd.snapshot      # 公開スナップショットを再生成
mix nerd.demo 5000     # k-匿名化の密度要件を数字で確認
mix nerd.gen.vault_key # VAULT_MASTER_KEY を生成
```
